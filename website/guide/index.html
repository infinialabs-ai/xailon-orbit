1. How XailonOrbit works

XailonOrbit has three parts. You install two of them; the third is hosted for you, or you can run it yourself.

Part Runs on What it does
xailon-orbitd Your computer A background daemon that starts your ACP agents (XailonCode by default), serves files and Git, and connects out to the relay.
XailonOrbit app Phone, tablet or browser Where you chat with agents, approve actions and review changes.
Relay Hosted, or your own server Forwards encrypted messages between the two. Default: wss://xailon-relay.infinialabs.ai/ws.

Both sides connect out to the relay, so you don't need to open ports, configure a router or run a VPN. They pair with a secret Pairing ID and derive end-to-end encryption keys from it, so the relay only ever sees ciphertext.

2. Requirements

  • Computer: macOS (Apple Silicon or Intel), Linux (x64) or Windows (x64). The daemon is a single native binary with no other dependencies.
  • Phone: iOS or Android, or a Chromium-based browser (Chrome, Edge) or Firefox for the browser extension.
  • Network: outbound HTTPS/WebSocket (port 443) to the relay from both devices. No inbound ports.
  • An agent: XailonCode is recommended. It is built in as the default; see Agents and ACP.

3. Install the daemon

Install xailon-orbitd on the computer where your code and agents live.

One-line installer (recommended)

Downloads the latest release from GitHub, verifies its SHA-256 checksum and installs to ~/.local/bin (macOS, Linux x64) or %LOCALAPPDATA%\Programs\xailon-orbitd (Windows x64). 

curl -fsSL https://xailon-orbit.infinialabs.ai/install.sh | sh   # macOS, Linux
irm https://xailon-orbit.infinialabs.ai/install.ps1 | iex       # Windows PowerShell

Set XAILON_ORBIT_VERSION=v0.4.0 to pin a version, or XAILON_ORBIT_INSTALL_DIR to change the location. Prefer to download by hand? Every build is on the releases page.

Homebrew (macOS, Linux)

brew install infinialabs-ai/tap/xailon-orbitd

Scoop (Windows)

scoop bucket add infinialabs https://github.com/infinialabs-ai/scoop-bucket
scoop install xailon-orbitd

npm Coming soon

The xailon-orbitd npm package (npm install -g xailon-orbitd, Node.js 22+) is not published yet. Use one of the options above.

From source

git clone https://github.com/infinialabs-ai/xailon-orbit.git
cd xailon-orbit
cargo install --path crates/daemon

Start it

xailon-orbitd start

start registers an autostart service (LaunchAgent on macOS, systemd --user on Linux, a scheduled task on Windows), starts the daemon in the background and prints your Pairing ID and a QR code. Run xailon-orbitd status at any time to see them again.

Prefer a terminal window? Run xailon-orbitd (or xailon-orbitd run) to run in the foreground without registering autostart.

cd xailon-orbit
corepack enable
pnpm install
pnpm --filter xailonorbit-extension build
  1. Chrome / Edge: open chrome://extensions, turn on Developer mode, click Load unpacked and choose packages/extension/dist/chrome.
  2. Firefox: open about:debugging#/runtime/this-firefox, click Load Temporary Add-on and choose packages/extension/dist/firefox/manifest.json.

Build the mobile app yourself

The mobile apps are built with Tauri 2. With the Android SDK or Xcode installed, run pnpm -C packages/xailonorbit run tauri android dev (or tauri ios dev). Push notifications need your own Firebase project; everything else works without one.

5. Pair your devices

Scan the QR code (recommended)

  1. On your computer, run xailon-orbitd status to show the QR code.
  2. Open XailonOrbit. On first launch it opens Settings (Relay & Remote Agent).
  3. Tap the scan button at the top right (Scan Pairing ID QR code) and point the camera at the code.
  4. XailonOrbit connects. The status changes from Connecting to Relay to connected and lists your agents.

The QR code is a link of the form xailonorbit://connect?pairingId=…. With a custom relay it also carries &relayUrl=…, so scanning configures both.

Enter the Pairing ID by hand

In Settings, paste the Pairing ID (it starts with xop1_) into the field and save. The app connects automatically. A typed Pairing ID always uses the default relay. To use a custom relay, scan the QR code instead.

More devices

Pair as many phones and browsers as you like with the same code. All paired devices share the same sessions. Settings remembers Recent pairings, so you can switch between several computers.

Keep the Pairing ID secret. Anyone who has it can use your agents and read files on your computer. Don't share screenshots of it. If it leaks, run xailon-orbitd reset.

6. Agents and ACP

XailonOrbit talks to agents through the open Agent Client Protocol (ACP). The daemon starts each agent as a local process and streams its work to your phone.

XailonCode (default)

XailonCode is listed first and selected by default. The daemon starts it as xailon acp:

  1. If the xailon CLI is on your PATH, the daemon uses it, together with your existing XailonCode configuration, models and logins.
  2. Otherwise, on Apple Silicon Macs, the daemon downloads a pinned XailonCode release, verifies its SHA-256 checksum and keeps it in the daemon's data directory.

To install XailonCode yourself (recommended, and the only option on other platforms):

curl -fsSL https://xailoncode.infinialabs.ai/install.sh | sh
xailon configure   # choose your model provider

Check that it works locally with xailon doctor before you connect from your phone.

Free

A built-in agent based on OpenCode, limited to its free models. Pick it to try XailonOrbit without any API key or login. It keeps its sessions separate from your own OpenCode.

Other ACP agents

Claude Code, Codex, Cursor, GitHub Copilot, Google Antigravity, OpenCode, Qwen Code, Kimi CLI and every other agent in the ACP registry are available. The daemon refreshes the registry in the background. For each agent it uses your installed CLI if one is on PATH; otherwise it downloads a managed binary or runs it through npx / uvx.

Sign in on the computer first. Agents use their own accounts and API keys. Run the agent once in a terminal (for example claude or codex) and sign in, then use it from your phone.

7. Using XailonOrbit

Sessions and working directories

Choose an agent, then tap New Session and browse to a folder on your computer (Create session here). Sessions are grouped by working directory and come from the agent itself, so sessions you start in a terminal show up too. A new session is created on your computer when you send its first message.

Approvals and questions

When an agent asks for permission or asks you a question, a card appears above the composer. Answers are delivered even if you reconnect or restart the app; the daemon keeps the request until you answer it or the turn ends.

Files, Git and previews

  • Browse files, changes, diffs and commit history of the session's repository.
  • Attach images, text and files (up to 5 MB). Files are saved on your computer for the agent to read.
  • Open the HTML pages, charts, maps and live screens that agents produce, right in the conversation.

Voice

When the composer is empty, the send button becomes a voice button. Hold to talk, release to send, and hear a short spoken summary of the reply.

Notifications

On iOS and Android, XailonOrbit notifies you when a prompt finishes. The notification contains only the agent and session IDs.

Keep your computer awake

xailon-orbitd awake active    # stay awake for an hour after the last activity
xailon-orbitd awake plugged   # stay awake while on external power
xailon-orbitd awake never     # default: normal sleep

8. Relay: hosted or self-hosted

The relay is a small, protocol-agnostic WebSocket service. It stores undelivered encrypted messages briefly so that nothing is lost when your phone goes offline, and it cannot read them.

Option A: the hosted relay (default)

Nothing to set up. Both the daemon and the app use wss://xailon-relay.infinialabs.ai/ws unless you choose otherwise.

Option B: Docker on your own server

docker run -d --name xailon-relay --restart unless-stopped \
  -p 39371:39371 -v xailon-relay-data:/data \
  ghcr.io/infinialabs-ai/xailon-relay:main

Or build it from source:

git clone https://github.com/infinialabs-ai/xailon-relay.git
cd xailon-relay
cargo run --release -- --bind 0.0.0.0:39371 --database /var/lib/xailon-relay/relay.sqlite3

Put it behind a TLS reverse proxy so clients can use wss://. For example, with Caddy:

relay.example.com {
  reverse_proxy 127.0.0.1:39371
}
Option Environment variable Default
--bind RELAY_BIND 0.0.0.0:39371
--database RELAY_DATABASE relay.sqlite3
--max-pending-messages RELAY_MAX_PENDING_MESSAGES 100000 per ID and direction
--max-pending-bytes RELAY_MAX_PENDING_BYTES 1 GiB per ID and direction
--pending-retention-secs RELAY_PENDING_RETENTION_SECS 3600 (1 hour)
--device-retention-secs RELAY_DEVICE_RETENTION_SECS 604800 (7 days)

Health check: GET /health returns 200 OK. Run exactly one relay process per database file.

Option C: your own Cloudflare account

The relay also ships as a Cloudflare Worker with Durable Objects (one per pairing), which runs on the Workers Free plan and needs no server. From the cloudflare/ folder of the relay repository: 

cd xailon-relay/cloudflare
npm install
npx wrangler login              # or set CLOUDFLARE_API_TOKEN and CLOUDFLARE_ACCOUNT_ID
npx wrangler deploy

Then attach a custom domain to the xailon-relay Worker in the Cloudflare dashboard (Workers & Pages → Settings → Domains & Routes), or set it under routes in wrangler.jsonc. To forward push notifications, add your Firebase service account with npx wrangler secret put FCM_SERVICE_ACCOUNT.

Point XailonOrbit at your relay

xailon-orbitd restart --relay-url wss://relay.example.com/ws
xailon-orbitd status   # the new QR code now includes your relay

Scan the new QR code on every device. The relay URL is saved for future starts. To go back to the hosted relay, run xailon-orbitd reset, which also rotates the Pairing ID.

9. Daemon commands

Command Description
xailon-orbitd start Register autostart, start in the background and show the pairing QR code.
xailon-orbitd stop Stop the daemon and remove autostart.
xailon-orbitd restart Restart the background service.
xailon-orbitd status Show service status, PID, relay URL, Pairing ID and QR code.
xailon-orbitd reset Rotate the Pairing ID and clear local connection state. Installed agents and history are kept.
xailon-orbitd awake [always|plugged|active|never|status] Control sleep prevention.
xailon-orbitd / xailon-orbitd run Run in the foreground.

Global options, saved for future starts:

xailon-orbitd restart --relay-url wss://relay.example.com/ws
xailon-orbitd reset --pairing-id <NEW_PAIRING_ID>

Run xailon-orbitd --help for the full reference.

10. Security model

  • Encryption: messages are sealed with XChaCha20-Poly1305 using keys derived with HKDF-SHA256 from the Pairing ID. The relay routes by a separately derived ID and never learns the secret.
  • No plaintext fallback: encrypted pairings never fall back to plaintext.
  • One credential: the Pairing ID is the only credential. Every paired device has full access, including to files on your computer, with no directory restriction.
  • Revoking access: individual devices can't be revoked. Run xailon-orbitd reset to rotate the ID and pair the devices you still trust again.
  • No open ports: the daemon only makes outbound connections.

11. Data and logs

OS Daemon data directory
macOS ~/Library/Application Support/xailonorbit/
Linux $ { XDG_DATA_HOME:-~/.local/share}/xailonorbit/
Windows %LOCALAPPDATA%\xailonorbit\

Logs are written to logs/xailon-orbitd.YYYY-MM-DD.log, one file per day, and the last 7 are kept. Start with RUST_LOG=debug for more detail. Save any logs you need before running reset.

12. Troubleshooting

Symptom What to do
Stuck on “Connecting to Relay” Check that the phone is online and that your network allows WebSocket connections to the relay. With a self-hosted relay, open https://your-relay/health in the phone's browser.
Connected to the relay, but the host never answers Run xailon-orbitd status on the computer. Make sure the Pairing ID and relay match the app, then xailon-orbitd restart.
“Relay connection was preempted” Another client is using the same device identity. Close it, or tap Reset App in Settings.
An agent fails to start Run the agent's CLI on the computer (for XailonCode: xailon doctor), sign in if needed, and check the daemon logs.
The app asks you to upgrade the daemon Update xailon-orbitd (see below). The app and the daemon should stay on matching versions.
Still stuck Run xailon-orbitd reset, tap Reset App in Settings, and scan the new code. Remote history is preserved.

Still need help? Email hello@infinialabs.ai. Never include your Pairing ID.

13. Update and uninstall

Update

xailon-orbitd stop
curl -fsSL https://xailon-orbit.infinialabs.ai/install.sh | sh   # or: brew upgrade xailon-orbitd / scoop update xailon-orbitd
xailon-orbitd start

If you move the binary to a different location, run xailon-orbitd restart from the new location so autostart uses the new path.

Uninstall

xailon-orbitd stop                    # stops the daemon and removes autostart
rm ~/.local/bin/xailon-orbitd         # or: brew uninstall xailon-orbitd / scoop uninstall xailon-orbitd

Then delete the data directory listed in Data and logs if you want to remove downloaded agents and settings.

14. Privacy

XailonOrbit has no accounts and no analytics. The relay forwards ciphertext and keeps undelivered messages for up to an hour. For push notifications, the app registers with Firebase Cloud Messaging and gives its token to your daemon. When a task finishes, the daemon sends the token, agent ID and session ID to the notification forwarder at xailon-relay.infinialabs.ai/push. Notifications never contain prompts or replies.
